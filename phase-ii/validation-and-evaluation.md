
# Phase II — AI-assisted development and evaluation

## Responsibility

The author defines expected system behavior, directs AI-assisted implementation using Claude, tests outputs, identifies issues, and refines the implementation.

Business acceptance is determined through human review, not presumed from a generated response.

## General evaluation cycle (illustrative)

1. **Define the requirement:** State user outcome, constraints and observable acceptance conditions.
2. **Request implementation:** Use AI-assisted development to propose functionality.
3. **Inspect the result:** Compare behavior against the requirement; investigate unexpected output.
4. **Test appropriate scenarios:** Include normal cases, missing data, exceptions, and user-role differences where applicable.
5. **Refine and retest:** Correct issues and seek user feedback in the approved pilot environment.

This is a generalized description of professional practice, **not** a copy of confidential test plans, prompts, approval criteria, or business rules.

## Reporting quality

Operational metrics should be clearly defined, checked for consistency, and labeled by their source and reporting interval.

Observed process improvements should be measured against comparable baseline work and approved before publication.

## Limitations

This file does not assert a particular software testing framework, production deployment pipeline, formal security certification, or independently audited performance result.
